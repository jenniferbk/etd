# Data View, Export All / Import, and Shared Codebook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Data view (Anna's horizontal layout) for one diagram or the whole library, an Excel round trip (Export all → code in Excel → Import with preview), and a per-group codebook of responsive-move kinds that can be revised mid-coding.

**Architecture:** Pure TypeScript modules in a new `src/data/` folder turn diagram documents into component groups and rows, turn cell edits into the live-collaboration `Op`s ETD already uses, and plan imports. Edits always travel as `Op`s. Library edits go to the existing `POST /api/diagrams/:id/live/ops`, which already works whether or not anyone has the diagram open. Canvas edits go through the diagram store, so live sync carries them. The server gains codebook tables and routes, a group data endpoint, and labeled versions. The codebook is mirrored into each library diagram's `styleConfig.subtypes`, so every existing reader (canvas labels, palette, SVG export, Properties) keeps working unchanged.

**Tech Stack:** React 19 + Zustand + Vite + Vitest (client, tests `src/**/*.test.ts`, no DOM); Express 5 + better-sqlite3 + zod + supertest (server). New dependency: `exceljs@4.4.0` (client, loaded with dynamic `import()`).

**Spec:** `docs/superpowers/specs/2026-11-16-data-view-design.md`. Reference assets in `docs/superpowers/specs/2026-11-16-data-view/`: `sample-3-episodes.xlsx` (approved look), `sample_generator.py` (row/column rules as runnable code), `research-codebook.seed.json` (34 kinds / 10 categories, extracted from the old VLOOKUP tab).

## Global Constraints

- Work on branch `data-view`. **Never push to `main`**: a push to main auto-deploys to the COMS lab server within 15 minutes. Jennifer decides when to merge.
- UI copy says **"responsive move"** / "Responsive move", never "support". Internal names (`type: 'support'`, `SupportElement`, `supportType`) do not change.
- Vetted status is **never inferred**. It starts blank and is set only by a person.
- `SAVE_SCHEMA_VERSION` becomes `'1.10'`. The change is additive: files at 1.9 or earlier load unchanged.
- Category is never stored on a move. It is always looked up from the kind in the codebook.
- Moves store the kind **id** in the existing `subtype` field, never the label.
- `action` moves never carry a kind (`subtype`). This is the existing store rule.
- Test fixtures are synthetic. Do not copy the real diagram JSON files (they contain student names) into the repo.
- Column order, headers, and group names come from one constant (`DATA_COLUMNS`, Task 5), shared by the grid and the export.
- Codebook labels are unique within a group, case-insensitive, among kinds that are not merged.

## Review Focus

1. **A sorted or filtered sheet is re-imported.** Rows are matched by hidden IDs. Expected: the same changes as the unsorted sheet. Test in Task 11.
2. **A kind is renamed in ETD between export and import.** Expected: no false change and no false conflict for moves whose Kind cell wasn't touched. Test in Task 11.
3. **Episode fields repeat on every row of an episode, and a coder edits only one row**, or edits two rows differently. Expected: one edit is applied, and two different edits are skipped with the reason "conflicting values." Test in Task 11.
4. **Moves pointing at nothing, a deleted element, or a folded qualifier.** Expected: unlinked moves land in the episode's `(not linked to a component)` group. Moves on a qualifier list under the qualifier's claim. Test in Task 5.
5. **Mixed timestamp formats** (`53:18`, `1:21:38`, `75:07-75:58`, blank, `0:41:32`). Expected: ordered by the first time in seconds, with blanks last for non-given components. Test in Task 5.
6. **A teammate has the diagram open while a library edit or import lands.** Expected: their canvas receives the ops and nothing is lost. Test in Task 3.

Widths are taken from `sample_generator.py`. `repeats` marks the episode and component columns that are grayed on continuation rows.
- Produces (`buildRows.ts`):
  - `parseTimeSeconds(t: string): number | null`: uses the first time in a range. `h:mm:ss` or `mm:ss`.

  - `buildGroups(input: DiagramDocInput, cb: Codebook | null): ComponentGroup[]`
  - `buildDataset(inputs: DiagramDocInput[], cb: Codebook | null): ComponentGroup[]`: episodes ordered by title (`localeCompare` with `numeric: true`), with `order` assigned sequentially.
  - `toRows(groups: ComponentGroup[]): DataRow[]`

Rules (spec §3.2–3.3; `sample_generator.py` is the executable reference, except that it strips title suffixes and infers status, which the plan does **not** do):
- Slot by `supportType`: `question` → question, `other` → other, anything else → untyped. Student and teacher moves share slots. `by` = attribution speaker with a leading `Student-` removed, falling back to `contributor`.
- Qualifiers whose `attachedTo.connectionId` resolves to a connection with a string `to` fold into that target's `qualifier` (joined `; `). Moves associated with a folded qualifier go to the target. Unattached qualifiers are their own component with part `Q`.
- Moves with no `associatedWith`, or one pointing at a missing element, go into one trailing group per episode with `component: null`.
- Component order: `given` first (by `position.y`), then by `parseTimeSeconds(time)` ascending (blank last), then `position.y`. Moves within a slot are ordered by time (blank last).
- Row count per group = `max(1, |untyped|, |question|, |other|)`.
- `links`: `→ <label>` for an element target, `→ link <fromLabel>→<toLabel>` for an arrow target, joined with `; `. `note`: texts of notes anchored to the component (`anchor.kind === 'element'`), joined with ` | `.
- infoBoxes produce no groups.
